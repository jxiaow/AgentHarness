# 国际化 (i18n) 规则

## 核心原则

所有用户可见的文本必须使用 `T()` 翻译函数，禁止硬编码。`T()` 自动使用全局 locale，无需传递参数。

## 规则

### 1. 翻译函数

使用 `T(key)` 获取翻译文本（自动使用全局 locale）：

```typescript
import { T } from './types';

// 正确
console.log(T('workspace'));

// 错误 - 硬编码
console.log('Workspace:');

// 错误 - 不需要传递 locale
console.log(T('workspace', locale));
```

### 2. 全局 Locale 设置

CLI 入口自动设置全局 locale：

```typescript
// src/cli/commands/index.ts
const locale = resolveLocale(extractFlag(argv, '--lang'), globalConfig.lang);
setGlobalLocale(locale);
```

所有后续的 `T()` 调用自动使用这个 locale。

### 3. 翻译键定义

在 `src/cli/commands/types.ts` 的 `UI` 对象中定义翻译键：

```typescript
const UI: Record<string, { en: string; zh: string }> = {
    workspace: { en: 'Workspace:', zh: '工作区：' },
    // ...
};
```

### 4. 交互式提示

交互式提示也必须使用翻译：

```typescript
// 正确
const selected = await choose(T('setupMultipleQtVersions'), versions, v => v);

// 错误
const selected = await choose('检测到多个 Qt 版本，请选择：', versions, v => v);
```

### 5. 诊断消息

诊断消息的 `message` 字段也必须翻译：

```typescript
// 正确
diagnostics.push(diag('setup.noServer', 'info', T('setupNoServer')));

// 错误
diagnostics.push(diag('setup.noServer', 'info', 'No server configured'));
```

### 6. Next Actions

nextActions 数组中的命令字符串不需要翻译（它们是命令），但描述性文本需要翻译。

## 检查清单

- [ ] 所有 `console.log()` 输出的文本使用 `T()`
- [ ] 所有 `diag()` 的 message 使用 `T()`
- [ ] 所有交互式提示（prompt/confirm/choose）使用 `T()`
- [ ] 翻译键在 `types.ts` 的 `UI` 对象中定义
- [ ] 英文和中文翻译都存在
- [ ] **不要传递 locale 参数给 T()**

## 例外

以下情况可以硬编码：
- 命令名称（如 `forja build`）
- 技术术语（如 `Qt`、`SDK`、`VS`）
- 文件路径和 URL
- JSON 键名
